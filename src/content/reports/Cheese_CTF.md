# Cheese CTF

I started by enumerating the machine with nmap and gobuster:

![gobuster.png](/images/reports/cheese_ctf/gobuster.png)

Going to the website we can see a login page, that is the only interesting thing on the page. I tried brute forcing the form with hydra, but I wasn’t successful. After looking online I found a SQLi payload that worked for the username: `' || 1=1;-- -`

Now we can see the following page:

![page.png](/images/reports/cheese_ctf/page.png)

Going to ‘Messages’ we get this:

![messages.png](/images/reports/cheese_ctf/messages.png)

Since PHP filter are used we can try using the `convert.base64-encode` filter to red the source code of the PHP pages. 

![curl.png](/images/reports/cheese_ctf/curl.png)

Now we can manipulate this to get a reverse shell. I got a PHP filter chain generator from: [https://github.com/synacktiv/php_filter_chain_generator/blob/main/php_filter_chain_generator.py](https://github.com/synacktiv/php_filter_chain_generator/blob/main/php_filter_chain_generator.py)

![payload.png](/images/reports/cheese_ctf/payload.png)

Now we sent our payload with curl:

![payload sent.png](/images/reports/cheese_ctf/payload_sent.png)

And thus we get a shell back:

![shell.png](/images/reports/cheese_ctf/shell.png)

Going to `/home/comte/.ssh` we can see that we can access `authorized_key`, so we can add a private key generated by us to get access to comte were the user flag is.

![key.png](/images/reports/cheese_ctf/key.png)

![comte keys.png](/images/reports/cheese_ctf/comte_keys.png)

And now we just ssh into comte’s account with the private key, and we got access:

![login.png](/images/reports/cheese_ctf/login.png)

Now, to get root, I ran `sudo -l` and got this:

![sudo -l.png](/images/reports/cheese_ctf/sudo_-l.png)

We need to use `exploit.timer` to gain root access. If we run exploit.timer we can see it gives an error that is because `OnBootSec=` is empty, so we just add 5s to correct it.

![changed file.png](/images/reports/cheese_ctf/changed_file.png)

![a.png](/images/reports/cheese_ctf/a.png)

So the `exploit.timer` triggers `exploit.service` which copies the `xxd` binary to `/opt` and set the SUID bit to the copied binary.

![opt.png](/images/reports/cheese_ctf/opt.png)

Now, if we go to GTFObin we get the command to add our previously generated SSH key to the `authorized_keys` of root.

![escalation.png](/images/reports/cheese_ctf/escalation.png)

After adding the key we can just log in with the same private key as root:

![root.png](/images/reports/cheese_ctf/root.png)
